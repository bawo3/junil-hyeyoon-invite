현재 브랜치의 변경된 코드를 철저히 리뷰해주세요.

## 리뷰 대상 파악

먼저 다음 명령으로 변경된 내용을 확인하세요:
- `git status` — 변경된 파일 목록
- `git diff main...HEAD` — main 대비 전체 변경 내용
- `git diff` — 아직 스테이징되지 않은 변경
- `git diff --staged` — 스테이징된 변경

## 리뷰 항목

다음 4가지 항목을 **순서대로**, **각 항목마다 별도 섹션**으로 작성하세요.

### 1. 타입 안정성 확인
- TypeScript/JavaScript의 경우 `any` 사용, 암묵적 타입 변환, null/undefined 처리 누락을 점검
- 함수 시그니처와 반환 타입이 명확한지 확인
- 타입 단언(`as`)이 안전하게 사용되었는지 확인
- 발견된 문제는 **파일경로:라인번호** 형식으로 인용

### 2. 잠재적 버그 찾기
- 경계 조건(빈 배열, null, 0, 음수 등) 처리 누락
- 비동기 처리 오류 (await 누락, Promise 처리 등)
- 상태 관리 문제, 사이드 이펙트, 메모리 누수 가능성
- 로직 오류, race condition
- 각 버그마다 **재현 시나리오**와 **영향도(높음/중간/낮음)** 표시

### 3. 성능 개선점 3가지 제안
- 정확히 **3가지**의 구체적인 개선 사항을 우선순위 순으로 제시
- 각 제안마다:
  - **현재 코드의 문제점** (어떤 비효율이 있는지)
  - **개선 방법** (구체적인 코드 예시 포함)
  - **예상 효과** (어느 정도 개선되는지)

### 4. 보안 취약점 체크
- OWASP Top 10 기준으로 점검: XSS, SQL Injection, CSRF, 인증/인가 누락, 민감 정보 노출 등
- 입력 검증, 출력 이스케이프 처리 확인
- 시크릿/API 키/토큰이 코드에 하드코딩되어 있는지 확인
- 외부 입력이 신뢰 경계를 넘는 지점 점검
- 발견된 취약점은 **심각도(Critical/High/Medium/Low)** 와 함께 표시

## 출력 형식

- 모든 설명은 **한국어**로 작성
- 코드 인용은 **파일경로:라인번호** 형식 사용
- 각 항목 끝에 **요약 한 줄** 추가
- 마지막에 전체 리뷰 결론 (머지 가능/수정 필요/재설계 권장 중 하나)을 명시
